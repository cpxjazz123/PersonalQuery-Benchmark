# Iteration #135 — Audit CLI `--audit-age` flag (JSON staleness check)

**日期**: 2026-07-21
**scope**: `PersoanlQuery/paper_claims_audit.py` add `--audit-age` argparse flag (relative age + staleness exit code); extend `_smoke_audit_regression.py` to 19 cases (Case S)
**prior**: audit JSON had `generated_at` ISO 8601 timestamp (iter #113) but no CLI affordance to check freshness. Reviewer / CI wanting to know "how stale is the audit JSON?" had to `stat -c %Y` the file, `jq .generated_at`, or `date` math manually. Iter #131/133/134 quick-check CLI flags covered content axes (status / worst-claim / per-section) but not temporal axis.

## §A 审稿意见

Reviewer / CI 想知道 "audit JSON 是不是 stale?" 当前必须:

1. `jq .generated_at result/personal_query/iterations/paper_claims_audit.json`
2. `date -u +%FT%T+00:00` (capture current UTC)
3. Manual subtract: now - generated_at
4. Mental 判断 "< 24h OK" / "> 24h stale — re-run"

iter #113 加了 `generated_at` 给 audit JSON 写到 disk 的时刻,但 no consumer CLI affordance。常见 CI use case: nightly cron re-run audit + push to repo,reviewer next morning 想 check "did CI run last night or stale from last week?"

后果: reviewer 早上看到 dashboard 第一反应 trust 内容(假设 fresh),实际上可能 stale 几天没 re-run。Audit JSON 是 source of truth — 如果 stale, paper claims 的 value mismatch 状态可能已经 changed since last run。

iter #135 fix: 新增 `--audit-age` CLI flag — 不 re-run audit,直接 read most recent audit JSON `generated_at` 字段,parse ISO 8601,compute elapsed time vs `datetime.now(timezone.utc)`,print:

```
audit JSON generated 2h 15m ago at 2026-07-21T10:30:00+00:00 (covers 17/17 claims)
```

Exit codes:
- **0** — age ≤ 24h (fresh, OK for review)
- **1** — age > 24h (stale, print WARNING to stderr suggesting re-run)
- **2** — JSON missing or `generated_at` field missing/malformed

`main()` handler (在 `--by-section` handler 之后):
```python
if args.audit_age:
    recent_path = Path(args.output) if args.output else OUT_PATH
    if not recent_path.exists():
        print(f"ERROR: audit JSON not found at {recent_path}; run audit first.", file=__import__("sys").stderr)
        return 2
    recent = json.loads(recent_path.read_text(encoding="utf-8"))
    generated_at = recent.get("generated_at", "")
    if not generated_at:
        print("ERROR: audit JSON missing 'generated_at' field; cannot compute age.", file=__import__("sys").stderr)
        return 2
    try:
        gen_dt = datetime.fromisoformat(generated_at)
    except ValueError:
        print(f"ERROR: audit JSON 'generated_at'={generated_at!r} is not valid ISO 8601.", file=__import__("sys").stderr)
        return 2
    now = datetime.now(timezone.utc)
    if gen_dt.tzinfo is None:
        gen_dt = gen_dt.replace(tzinfo=timezone.utc)
    delta = now - gen_dt
    total_seconds = int(delta.total_seconds())
    hours, rem = divmod(total_seconds, 3600)
    minutes, seconds = divmod(rem, 60)
    days, hours = divmod(hours, 24)
    if days > 0:
        age_str = f"{days}d {hours}h {minutes}m ago"
    elif hours > 0:
        age_str = f"{hours}h {minutes}m ago"
    elif minutes > 0:
        age_str = f"{minutes}m {seconds}s ago"
    else:
        age_str = f"{seconds}s ago"
    n_total = recent.get("n_claims", 0)
    n_audited = recent.get("n_audited", n_total)
    print(f"audit JSON generated {age_str} at {generated_at} (covers {n_audited}/{n_total} claims)")
    if delta.total_seconds() > 24 * 3600:
        print(f"WARNING: audit JSON is stale (>{24}h old); consider re-running `bash PersoanlQuery/_run_audit_ci.sh`.", file=__import__("sys").stderr)
        return 1
    return 0
```

## §C 关键改动点

1. **No re-run audit**: `--audit-age` 跳过 evaluate_claim loop,直接 read JSON file。Runtime <100ms vs full audit (~1-2s)。

2. **Triple exit code semantics**:
   - `0` (fresh) — actionable, JSON safe to use for review
   - `1` (stale) — non-zero so CI/scripts can detect via `$?`,但 stderr WARNING 明确 "consider re-running"
   - `2` (bad-input) — JSON missing or malformed, distinct from "stale but readable"

3. **Three-tier relative age format**:
   - `>= 1 day`: `"3d 5h 22m ago"`
   - `>= 1 hour`: `"2h 15m ago"`
   - `>= 1 minute`: `"45m 12s ago"`
   - `< 1 minute`: `"37s ago"`
   
   Each tier 选择最 relevant granularity — reviewer 看到 "3d 5h ago" 一眼知道 stale,vs "45m 12s ago" 知道 fresh enough。

4. **Naive datetime fallback**: 如果 `generated_at` 没有 tzinfo (e.g. older audit JSON written without `+00:00`),treat as UTC (跟 iter #113 timestamp format 一致)。`datetime.fromisoformat` Python 3.11+ handles ISO 8601 with tz;Python 3.10 also works for `+00:00` format。

5. **`(covers 17/17 claims)` suffix**: 跟 iter #131 `--status-summary` 1-line format 类似 — output 包含 enough context (cover count) 让 reviewer 不需要 also run `--status-summary`。

6. **`--output` flag respected**: reviewer 想 `--audit-age --output /custom/path.json` 跟其他 mode 语义一致。

7. **WARNING to stderr, not stdout**: 让 `audit JSON generated ... ago at ... (covers ...)` 留在 stdout (greppable / parseable),stale warning 去 stderr (visible in CI logs but separate from output data)。
